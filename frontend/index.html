Setup Account AWS

Crea nuovo job di analisi

Prima di iniziare: serve un accesso in sola lettura all'account AWS, di solito tramite il portale AWS SSO (IAM Identity Center). Da terminale: aws sso login --profile <profilo>.

  1. Account ID: 12 cifre, si legge in alto a destra nella console AWS o con aws sts get-caller-identity --profile <profilo> --query Account --output text.
  2. Regioni: lascia all per analizzare tutte le regioni abilitate.
  3. Tenant ID: non è un dato AWS, è un nome scelto da voi per raggruppare i job dello stesso cliente (es. application, mur, idm).
  4. Role ARN: facoltativo, vedi il pulsante ⓘ accanto al campo.

Usa i pulsanti ⓘ accanto a ogni campo per i dettagli.

Il numero di 12 cifre che identifica l'account AWS da analizzare. Per trovarlo:

  • Portale AWS SSO (IAM Identity Center): è indicato sotto il nome di ogni account nell'elenco.
  • Console AWS: clic sul nome utente in alto a destra, voce Account ID.
  • AWS CLI, dopo aws sso login --profile <profilo>: aws sts get-caller-identity --profile <profilo> --query Account --output text
  • Nel file %USERPROFILE%\.aws\config: valore sso_account_id del profilo.
"all" = tutte le regioni abilitate sull'account; oppure una o piu' regioni separate da virgola.

Consigliato: all. L'estrazione interroga tutte le regioni abilitate sull'account; quelle bloccate dalle policy dell'organizzazione (SCP) vengono segnalate come negate e saltate.

Per limitare l'analisi, indica una o più regioni separate da virgola, es. eu-south-1,us-east-1 (us-east-1 contiene anche i certificati ACM usati da CloudFront). Elenco delle regioni abilitate: aws ec2 describe-regions --profile <profilo> --query "Regions[].RegionName" --output text

Non è un dato AWS e non va recuperato da nessuna parte: è un identificativo scelto da voi per il cliente o il perimetro a cui appartiene l'account (es. application, mur, idm, cineca).

A cosa serve: le regole di tagging approvate (pagina Regole) e il nodo Tenant del grafo sono associati al tenant. Usa sempre lo stesso valore per tutti gli account e job dello stesso cliente, così le regole già approvate vengono riutilizzate. Consigliato: minuscolo, senza spazi.

Nota: oggi questo valore non viene usato dall'estrazione. Agent 1 usa le credenziali del proprio ambiente: il profilo SSO (AWS_PROFILE) oppure il ruolo indicato in AWS_ASSUME_ROLE_ARN nel file .env. Puoi lasciare il campo vuoto.

Se serve l'ARN del ruolo di sola lettura (per configurare AWS_ASSUME_ROLE_ARN):

  • Console IAM dell'account: Ruoli, cerca il ruolo di lettura (es. FinOps_ReadOnly), copia il campo ARN.
  • AWS CLI: aws iam list-roles --profile <profilo> --query "Roles[?contains(RoleName,'ReadOnly')].Arn" --output text
  • Con SSO il ruolo si chiama AWSReservedSSO_<PermissionSet>_…; il ruolo attuale è indicato da aws sts get-caller-identity --profile <profilo> (campo Arn).
  • Formato: arn:aws:iam::<account-id>:role/<nome-ruolo>.
